# 双智能体交易执行回放说明书

适用分支为 `frontend_UI`。本文按当前网页和内置回放编写，适合本地操作、课堂演示和答辩复核。

## 1. 项目在演示什么

A、B 各有一笔 100,000 股的买入母单，在同一个合成限价订单簿里执行。系统把 30 分钟划成 60 个决策步，每步 30 秒。两个智能体分别用自己的 Q 表决定是否下单、报什么价和提交多少。市场根据订单簿和模拟订单流撮合，再把成交、余量和价格变化反馈给下一步。

网页播放已经生成的冻结策略回放。切换时间轴会重新显示该步记录，切换情景会加载另一份完整数据。默认两份样例来自 `wuxinhan-1@7906ab8`，使用同一个第 500 回合检查点和回放种子 20261105。检查点 500 是训练轮次，60 是单次模拟的决策步数。

## 2. 启动与通用操作

在 VS Code 的 PowerShell 终端进入前端目录：

```powershell
cd "E:\中科大\multi-agent-execution\marl-trade-execution\frontend"
npm install
npm run dev
```

依赖已经安装时可直接运行 `npm run dev`。打开终端输出的 `Local` 地址。停止服务按 `Ctrl+C`。如需验证生产构建，可执行 `npm run build`。

| 控件 | 用法与结果 |

| 时间轴 | 拖动滑块、点击下方刻度，或点击上一步、下一步。手动定位会暂停播放。 |

## 3. 总览回放

总览适合先看当前市场和两家的动作，再定位值得讲解的时间步。新版内置回放打开时会优先定位到出现新单部分成交的第一步。

| 界面 | 如何解读 |
|---|---|
| 当前中间价 | 所选步撮合前的中间价。图表中的时间点也使用撮合前的价格。 |
| 当前步数 | 当前选中的决策步与全局步数，例如 58 / 60。 |
| A/B 步前剩余 | 智能体做该步决策前尚待买入的母单股数。最后一步切换成「期末剩余」，显示本步撮合和兜底完成后的余量。 |
| 基金 A/B 卡片 | 本步决策显示动作名称，本步提交显示智能体发出的新订单量。Q 值是选中动作在该状态下的估值。横线表示没有可展示的已尝试估值。 |
| 已完成、普通成交、兜底 | 「已完成」平时对应步前累计完成率，最后一步显示期末完成率。「普通成交」是该步主动与被动成交之和；最后一步如触发兜底，会另列兜底量。 |
| 中间价轨迹 | 实线覆盖已回放区间，虚线展示记录中后续的价格路径，亮点是当前步。点击绘图区可跳到最近的时间步。虚线来自已经生成的回放记录。 |
| 共同市场反馈 | 联合提交是 A、B 的本步新提交之和，联合实际成交可含前序挂单的成交和期末兜底。临时冲击和下一中间价描述撮合及价格转移。 |
| 决策详情 | 点击某一家卡片上的链接，进入同一步、同一基金的决策页。 |

只要本步没有成交，提交多少新单都不会减少母单余量。反过来，智能体即使选择等待，只要已有挂单成交，母单也会减少。

## 4. 智能体决策

在页首切换「基金 A」或「基金 B」，查看同一时点各自的状态与候选动作。两边先根据共同的市场快照分别做决定，然后市场统一撮合。

| 界面 | 如何解读 |
|---|---|
| 当前中间价、剩余订单、剩余时间 | 当前决策可使用的步前状态。第 60 步决策时仍有最后 30 秒，其余量可能大于总览里显示的期末余量。 |
| 对手上期成交 | 对手上一时间步的实际成交量。它作为状态输入，不代表当前步已经知道对手会怎么下单。 |
| 状态编码 | 后端用分箱把连续状态映射到 Q 表的一行。新版依次包含时间阶段、执行进度、价格偏离、对手上期成交、自身报价档位、挂单余量、前方队列、挂单年龄和是否最后一步。编码数字是档位。 |
| 执行进度比 | 剩余母单量 ÷（剩余步数 × TWAP 基准量）。大于 1 表示剩余任务多于原均匀计划在剩余时间内对应的量。 |
| 价格偏离 | 当前中间价相对初始中间价的变化，用基点表示。 |
| 动作档位与 Q 值 | 显示各档候选动作、候选股数、Q 值、访问次数与状态。选中行标记「已选择」，未尝试动作的 Q 值显示横线。候选股数表示该档拟提交量。 |
| 基金的选择 | 显示最终动作、实际提交量、选择依据、新单限价和撮合结果。没有新单时新单限价显示横线。 |
| 订单状态 | 可看到全部成交、部分成交、剩余挂单、换单撤销、挂单到期、IOC 撤销及期末撤销或兜底。一次撮合可以同时出现多项事件。 |
| 同步执行后的市场反馈 | 把两个智能体的结果放在同一时点，展示两家实际成交、联合提交和下一中间价。点击「查看成本」可到市场页复核。 |

### 五种动作

TWAP 基准量是母单股数除以决策步数。默认约为 1,666.67 股。实际可提交股数还受步前剩余母单限制。买一是当前最高买价，卖一是当前最低卖价，一档是模拟订单簿的最小报价间距。

| 动作 | 新提交量 | 报价和执行方式 |
|---|---:|---|
| 等待 / 保留挂单 | 0 | 不提交新单。如果旧挂单仍有效，它可继续参与撮合。 |
| 深档限价 | 0.5 × TWAP | 报在买一下一档，争取较低买价，需要卖方订单流到达该价位并消耗前方队列。 |
| 买一限价 | 1 × TWAP | 报在最高买价，按模拟队列等待被动成交。 |
| 价差内限价 | 1.5 × TWAP | 报在买一上一档。在默认配置下仍位于买卖价差内，以更积极的报价排队。 |
| 可成交限价 IOC | 2 × TWAP | 买入限价设在卖一上一档，立即尝试成交限价内的可见卖盘，未成交余量立即撤销。 |

重新提交限价单会撤销旧挂单并重新排队。被动挂单默认有效期 4 个时间步，即 2 分钟。期末兜底由环境在普通撮合结束后触发，动作表里没有对应的第六个动作。

### 本步决策的常见情况

阅读时先看**选了什么动作**，再看**实际发生了什么**。例如「买一限价」是智能体的动作，「部分成交」是市场对该动作或已有挂单的反馈。

| 页面显示 | 具体含义 |
|---|---|
| 等待 / 保留挂单 | 本步提交 0 股。旧挂单如仍有效，会继续参与撮合，所以本步仍可能有成交。 |
| 深档限价 / 买一限价 / 价差内限价 | 三种被动报价，从买一下一档、买一到买一上一档。报价和股数一起变化。报价更积极有机会更早成交，结果仍取决于订单流和队列。 |
| 可成交限价 IOC | 以卖一上一档为价格上限，立即尝试买入可见卖盘。可能全部成交、部分成交或零成交，未成交余量立即撤销。 |
| 已选择 / 可比较 | 「已选择」是本步实际采用的动作。「可比较」表示该动作已在同一离散状态下被尝试，且可参与此次 Q 值比较。 |
| 未尝试 / Q 值 — | 「未尝试」表示当前状态下该动作的访问次数是 0。若可选动作都没有记录，当前限价单版使用买一限价作为默认动作，总览中的选中 Q 值显示横线。 |
| 期限受限 | 主要用于旧版回放。动作不满足该步的期限可行性限制，不能参加选择。新版限价单回放允许按模型规则选择低档动作，期末兜底由环境处理。 |
| 最高 Q 值 / 并列最高 | 在已尝试的可选动作中比较。负数也有大小，例如 −0.10 高于 −0.14。若有并列，页面显示回放记录中实际选到的动作。 |

| 成交或订单状态 | 具体含义 |
|---|---|
| 提交大于 0，实际成交为 0 | 下了新单，但该步没有买到股票。普通限价单可能继续挂着；IOC 的未成交量会撤销。 |
| 全部成交 / 部分成交 | 全部或部分执行了该步参与撮合的新单或旧挂单。这里说的是参与撮合的子单，母单是否买完要看步后剩余。 |
| 剩余挂单 | 撮合之后仍留在订单簿里的子单余量。它只是母单未完成量的一部分。 |
| 换单撤销 | 新提交替换了此前尚未成交的挂单，撤销的是旧单余量。 |
| 挂单到期 | 旧挂单达到有效期后被移除，未买到的股数仍留在母单里。 |
| IOC 撤销 | 本步的主动限价单没能立即买到全部提交量，撤销的是该单剩余部分。 |
| 期末撤销 / 期末兜底成交 | 到截止时间，仍挂着的普通子单会结束；启用兜底时，环境会另行成交母单余量。兜底股数单列，不算作智能体选出的普通子单。 |
| 无成交或订单变动 | 本步没有记录普通成交、剩余挂单、撤单或兜底等事件。 |

可在正常波动的第 19 步查看 A 的「买一限价 → 部分成交 + 剩余挂单」，在第 43 步查看 A 的「IOC 撤销」，在第 60 步查看环境兜底。复核余量时用「步前剩余 − 普通成交 − 兜底成交」。

### 本步解读

点击「本步解读」会暂停播放，并以六项内容组织当前基金的完整决策记录：

1. **输入状态**。展示已过时间、剩余时间、母单待买、中间价、报价价差及单边手续费。
2. **对手线索**。说明模型使用的上期成交量，并回看最近两步对手的动作和成交。历史回看用于讲解，Q 状态使用的仍是上期成交量。
3. **智能体动作**。列出动作、提交股数和新单限价。
4. **模型依据**。并排显示当前状态已尝试、可比较的候选 Q 值和选择规则。当前限价单版本若没有已尝试动作，会回退到买一限价。
5. **环境反馈**。列出实际成交、步后剩余、中间价变化和撤单等事件。
6. **业务解释**。结合动作类型说明是等待、排队、立即尝试成交还是由期末规则补齐。

## 6. 回合总结

这一页显示整局统计，时间轴用于返回定位过程。点击「从头回放」会回到总览并从第 1 步开始播放。

| 界面 | 如何解读 |
|---|---|
| 总实施缺口 | 以初始中间价作为基准的整局执行成本，使用母单名义金额归一化。买入任务中，其他条件相同，数值越低代表执行越便宜。 |
| 完成率和未完成股数 | 按整局实际成交统计。启用兜底时，完成率包含兜底成交，比较策略时应同时看兜底量。 |
| 期末兜底股数及成本 | 分别显示兜底成交数量及其对总实施缺口的贡献。该贡献已包含在总成本中。 |
| 回合成本构成 | 展示累计价格漂移、成交价差、临时冲击和手续费。存在未完成母单时，机会成本以期末中间价相对初始价的变化估算。 |
| 动作分布 | 柱状图统计每种动作被选中的次数，包含等待。动作次数与成交股数是两种统计口径。 |
| 成本复算、策略表哈希 | 验证已成交成本与期末机会成本能否复算到总成本，以及回放记录中的策略表前后哈希是否一致。 |

## 7. 应用到的理论

### 多智能体博弈与 Q-learning

这是一个有固定终止时间的多智能体序贯决策问题。A、B 各自控制子单，在同一市场中竞争流动性。一方的报价、排队和成交会影响另一方的撮合机会或下一步价格。两家各自追求执行进度和成本，结果无需是一赢一输。使用智能体的理由是它可以随状态变化调整动作。是否优于固定拆单，需要在相同撮合规则和完单条件下比较。

Q-learning 把某状态下采取某动作的未来累计奖励估成 Q 值。后端训练时使用如下时序差分更新：

```text
Q(s,a) ← Q(s,a) + α × [r + γ × max Q(s',a') − Q(s,a)]
```

其中 α 是学习率，γ 是折扣因子，r 是本次反馈，终局没有下一步价值。内置样例对应的模型默认学习率 0.15、折扣因子 0.98。训练探索率从 0.35 逐步降到 0.05。网页播放冻结策略，探索率为 0，比较当前状态下已尝试的可选动作。Q 值体现模型奖励下的估值，负值之间仍可比较，例如 −0.1019 高于 −0.1442。

### 限价订单簿与执行进度

被动限价单先排队，卖方主动订单流消耗前方队列后才可能成交。主动 IOC 则消耗报价上限以内的可见卖盘。这个机制把「决策提交量」与「环境实际成交量」分开，也体现了执行中的基本取舍：更积极的报价有机会更快成交，但可能付出更高价差和市场冲击；等待可能节省价格成本，也可能把未完成量留到期末。

### 执行成本、奖励与收盘兜底

1 bp 是 0.01%，默认单边手续费 30 bp 是成交名义金额的 0.30%。已成交实施缺口可理解为「实际含费成交金额减去按初始中间价计算的同等股数金额」，再除以初始母单名义金额并换算成 bp。价格相对初始价的变动、报价相对本步中间价的差、成交冲击与手续费构成经济成本。训练奖励以降低成本为导向，并根据运行模式处理终局未完成量。经济成本与训练惩罚应分别解读。

在默认兜底模式，第 60 步先做普通撮合，剩余母单再按合成收盘价格一次性成交。A、B 的兜底余量合计参与定价，基于当步中间价加半价差及随兜底量上升的冲击。合成收盘规则使两家可以显示 100% 完成。**评价智能体本身，应同时报告普通成交比例、兜底量和总经济成本。**

## 8. 可以现场复现的样例

### 例一：正常波动，第 19 步，基金 A

1. 在「回放配置」选择正常波动，点击「智能体决策」，选择基金 A，并定位到第 19 步。
2. 打开「本步解读」。A 步前待买 100,000 股，剩余 21 分钟，中间价约 99.9018，对手上一步成交 0 股。
3. 已尝试的两种动作中，买一限价 Q 值约 −0.1019，高于价差内限价的 −0.1442。A 选择买一限价，提交 1,666.67 股。
4. 市场实际成交 276.67 股，新单还挂着 1,389.99 股，母单剩余 99,723.33 股。旧挂单撤销量单列。

这个例子可用来讲清楚「选动作 → 重新报价 → 部分成交 → 更新母单余量」。如需演示 IOC 未成交余量撤销，可在同一场景查看基金 A 的第 43 步。

### 例二：正常波动，第 58 至 60 步

| 时间点 | A | B |
|---|---:|---:|
| 第 58 步开始时剩余 | 81,791.59 股 | 89,440.92 股 |
| 第 59 步普通成交 | 0 股 | 2,056.29 股 |
| 第 60 步普通成交 | 0 股 | 0 股 |
| 第 60 步收盘兜底 | 81,791.59 股 | 87,384.63 股 |
| 期末剩余 | 0 股 | 0 股 |

本局 A 普通撮合完成 18.21%，B 完成 12.62%。计入兜底后，A 的总执行成本约 57.65 bp，B 约 60.06 bp。这个样例说明 A 在这一局的普通成交比例更高、总成本更低。两家使用同类算法，判断哪套策略更稳定，需要在多组配对市场情景下比较，并检验交换角色后的表现。
