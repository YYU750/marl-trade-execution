# A/B 双边同步学习模型的主要运行机制

## 1. 模型定位

当前主模型是 A、B 双边同步学习的多智能体交易执行仿真。两家机构各自持有买入母单，同时面对时间限制、交易成本和对手订单流。A、B 都使用表格型 Q-learning，双方当前动作共同改变成交成本和后续市场价格。训练后，系统冻结策略检查点并进行交叉对局，分析策略互动、训练稳定性和候选集最佳反应。

模型不调用生成式模型服务，不连接真实行情、账户或下单接口。价格、冲击和状态转移是教学假设，模拟结果不等于真实市场结论。

课堂资料规定收盘前 30 分钟执行，没有指定决策步长。项目将其离散为每 30 秒一步，共 60 步；该步长是建模选择。

## 2. 一回合如何运行

每回合开始时，A、B 各有 100,000 股待买订单，中间价为 100。每个 30 秒时间步按以下顺序运行：

| 步骤 | 运行内容 |
|---|---|
| 1. 共享观察 | 市场给出当前时间、中间价等共同交易前状态；每个 Agent 同时读取自己的剩余订单和对手上一期成交量 |
| 2. 同步选动作 | A、B 分别读取自己的 Q 表，按各自可行动作选择本步下单量；任何一方都看不到对方本步的新动作 |
| 3. 统一撮合 | 环境将 A、B 子单合并计算，更新成交价、手续费、订单剩余量和下一步中间价 |
| 4. 双边反馈 | 环境根据各自成交、剩余库存和终端状态计算奖励，分别更新 A、B 的 Q 表 |
| 5. 记录运行 | 保存动作、奖励、成本、完成率及训练诊断 |

A、B 先完成本步动作选择，市场再处理共同订单流。Q 表更新只影响之后的决策，不会改写本步已经选定的动作。双方策略在训练中都持续变化，因此任一 Agent 面对的对手策略和状态转移分布也会变化，学习过程具有非平稳性。

## 3. Agent、状态与动作

### Agent 职责

| 对象 | 机制 |
|---|---|
| Agent A | 以自身库存、时间、价格和 B 上一步成交量为观察，输出买入子单并更新自己的 Q 表 |
| Agent B | 以自身库存、时间、价格和 A 上一步成交量为观察，使用独立 Q 表同步学习 |
| 市场环境 | 统一计算成交、费用、冲击和下一时点价格，不作为学习型 Agent |
| 评估器 | 冻结训练检查点，组合测试 A/B 策略并计算成本、稳定性和候选集响应 |

### 状态

每个 Agent 都使用离散状态：

- 当前时间步：0 至 59；
- 自己的剩余母单比例：0 至 10 档；
- 中间价相对初始价的偏离：小于 −4bp、−4 至 −1bp、−1 至 1bp、1 至 4bp、大于等于 4bp；
- 对手上一期成交量相对 TWAP 基准份额的档位：低于 0.25 份、0.25 至 1.25 份、大于等于 1.25 份。

波动率影响价格扰动和库存风险，但不在当前 Q 状态中。A 观察 B 上一期成交量，B 观察 A 上一期成交量。系统没有使用对手身份识别、意图分类或未来动作预测模型。

### 动作与完成约束

TWAP 基准份额为母单除以步数，即约 1,666.67 股。双方动作集合相同：

| 动作 | TWAP 倍数 | 单步数量约值 |
|---|---:|---:|
| 等待 | 0 | 0 股 |
| 半份 | 0.5 | 833 股 |
| 基准份 | 1.0 | 1,667 股 |
| 较大份额 | 1.5 | 2,500 股 |
| 最大份额 | 2.0 | 3,333 股 |

若本步之后剩余时间内即使每步都买入最大份额仍无法完成订单，系统会提高当前允许的最小动作：

```text
本步最低可行量 = max(0, 当前剩余订单 − 后续剩余步数 × 2 × TWAP 基准份额)
```

此约束对 A、B 一致，避免策略通过少成交来获得表面上较低的成本。

## 4. 市场成交、冲击与奖励

### 订单冲击与成交价

当前市场参数包括半价差 2bp、临时冲击系数 0.35bp/份、永久冲击系数 0.20bp/份。设 `qA` 和 `qB` 为双方子单、`λB` 为对手影响系数，则：

```text
合并冲击量 = qA + λB × qB
临时冲击 = 0.35bp × 步长分钟数 × 合并冲击量 / TWAP 基准份额
毛成交价 = 当前中间价 × [1 + (半价差 + 临时冲击) / 10,000]
手续费/股 = 当前中间价 × 单边费率 / 10,000
含费成交价 = 毛成交价 + 手续费/股
```

双方子单共同进入临时冲击，所以同一回合的订单流会影响两边成交成本。永久冲击影响下一时点中间价：

```text
永久冲击 = 0.20bp × 步长分钟数 × 合并冲击量 / TWAP 基准份额
下一时点中间价 = 当前中间价 × [1 + (外生随机扰动 + 永久冲击) / 10,000]
```

正常波动率是每分钟标准差 2.5bp；两倍波动测试将其乘以 2。半价差和手续费显式计入成本。

### 奖励和结果成本

每个 Agent 的逐步奖励为：

```text
本步奖励 = −本步成交量 / 母单 × 本步实施缺口
          −库存风险权重 × 剩余订单比例 × 波动率系数 × 步长
终局惩罚 = −未完成订单比例 × 1,000bp
```

最终实施缺口与累计奖励不是同一口径。结果成本拆为成交部分毛执行缺口、显式手续费和未成交订单机会成本：

```text
总实施缺口 = 成交部分毛执行缺口 + 手续费成本 + 未成交机会成本
```

因此报告同时列出成本、完成率和未完成股数；不能只凭累计奖励或 Q 值判断策略经济效果。

## 5. 双边学习和检查点

A、B 各自维护独立 Q 表。训练使用 epsilon-greedy，探索率从 0.35 随回合线性下降到 0.05；学习率 α 为 0.15，折扣因子 γ 为 0.98。一次更新为：

```text
Q(s,a) ← Q(s,a) + α × [r + γ × max Q(s',a') − Q(s,a)]
```

下一状态只在可行动作中取最大 Q 值。A 与 B 先分别选择本步动作，环境完成共同撮合后，再把各自奖励反馈到各自 Q 表。

默认每个训练种子训练 500 回合，检查点为 0、100、200、300、400、500。第 0 回合作为未训练策略参考。训练场景为正常波动；训练期间 A、B 始终互为学习型对手。

## 6. 冻结交叉评估、稳定性与最佳反应

训练完成后，所有检查点 Q 表冻结。每个训练运行内，将 6 个 A 检查点与 6 个 B 检查点两两组合；每种组合在正常波动和两倍波动下各使用 30 个配对随机种子。默认共：

```text
5 个训练种子 × 6 个 A 检查点 × 6 个 B 检查点
× 2 个波动场景 × 30 个评估种子 = 10,800 回合
```

交叉评估不继续更新策略。相同评估种子为不同策略组合提供相同外生价格冲击，策略带来的价格路径变化作为内生反馈保留。

稳定性诊断包括训练滚动奖励、训练滚动成本、跨种子成本差异、已访问状态数、Q 表状态数，以及 A/B 同检查点组合的对角线表现。若这些指标随检查点波动，或不同训练种子给出不同策略，不应声称收敛。

对固定的 B 检查点，A 的候选集最佳反应是当前训练保存的 A 检查点中成本最低者；对固定的 A 检查点，B 同理。候选集后悔值为当前检查点成本减去该有限集合内的最低成本。该计算不是全局最优搜索，也不单独证明纳什均衡。

2026-11-03 已完成默认配置运行。下表的成本先在每个训练种子内对评估种子取均值，再汇总训练种子；± 为训练种子最终单元格均值的标准差。

| 波动场景 | A 实施缺口 | B 实施缺口 | 完成率 |

## 8. 运行入口和输出

在本目录运行主模型：

```powershell
python .\run_experiment.py
```

也可直接调用实现脚本：

```powershell
python .\run_advanced_self_play.py --episodes 500 --training-runs 5 --eval-seeds 30 --checkpoint-interval 100 --seed 20261103
```

默认输出在 `outputs/advanced_self_play/`：

- `training_episodes.csv`、`checkpoint_training_diagnostics.csv`：逐回合训练表现与检查点诊断；
- `cross_play_raw.csv`、`cross_play_summary.csv`：交叉对局逐回合数据和汇总；
- `self_play_stability.csv`：同检查点对局和训练稳定性指标；
- `candidate_best_response.csv`：有限候选检查点的最佳反应和后悔值；
- `qtable_run*_A.json`、`qtable_run*_B.json`：每次训练的最终双方策略表；
- `checkpoint_qtables_run*.json`：全部检查点的双方 Q 值和动作访问数；
- `findings.md`、`run_manifest.json`：运行发现、限制、参数、种子和脚本哈希。

## 9. 适用边界

本模型是单资产、单向买入、批次撮合仿真，不包含真实历史行情校准、完整订单簿、队列优先级、隐藏流动性、真实部分成交或交易接口。双方目标和执行规则相同，结果不能概括现实市场全部的机构竞争机制。训练中的双边策略非平稳；检查点评估和多种子诊断用于观察该现象，但不会自动保证收敛。旧版单学习者/固定规则对手代码保存在 `run_standard_benchmark.py`，主模型和本文均以双边同步学习为准。
