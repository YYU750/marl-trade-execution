# 学习型方案 C 机制详解

本文按程序实际运行顺序，说明多智能体交易模型中的学习型方案 C。重点是 C 如何让每个 Agent 自主决定**是否加急、什么时候加急、加急到哪一档**，以及这些决定如何通过模拟订单簿和 Q-learning 产生后续影响。

## 1. 任务设置与方案 C 的位置

模型模拟两家机构 A、B 在收盘前执行买入母单。默认参数如下：

| 参数 | 当前设置 |
|---|---:|
| 执行窗口 | 30 分钟 |
| 每步长度 | 30 秒 |
| 决策步数 | 60 步 |
| 每家母单 | 100,000 股 |
| 单边手续费 | 30 bp |
| 学习率 α | 0.15 |
| 折扣因子 γ | 0.98 |
| 探索率 ε | 随训练回合由 0.35 逐步降至 0.05 |

每家机构并不是只有一个 Q 表，而是有两个相互配合、分别更新的表格型决策头：

1. **普通执行 Q 头**：从等待/保留、被动限价档、价差内限价和基准 IOC 等动作中选本步基础动作。
2. **学习型 C-Q 头**：只在进度落后时决定本步是否加急，以及选择哪档 IOC 报价上移幅度。

因此，系统共有 A 的普通 Q 表、A 的 C-Q 表、B 的普通 Q 表、B 的 C-Q 表。C 头不是第三个独立交易机构，也不是固定规则覆盖；它是每个交易 Agent 内部负责截止加急选择的学习模块。

## 2. Agent 怎样判断“落后”

程序在每步下单前，使用当前剩余母单量与剩余时间的线性计划量进行比较。

记：

- `Q`：母单总量；
- `H`：总时间步，本模型为 60；
- `t`：当前时间步的零起始编号，范围为 0–59；
- `R_t`：当前本步决策前的剩余母单量。

当前步开始时，线性计划要求剩余完成量为：

```text
S_t = Q × max(H − t, 1) / H
```

若 `R_t ≤ S_t`，Agent 尚未落后。C 头此时没有加急选择，固定返回 `no-C`，普通执行 Q 头照常做决策。

若 `R_t > S_t`，Agent 已落后。此时 C 头开放 `no-C` 和三种加急行动。因为当前步也包含在 `H − t` 中，所以当前步计划执行的份额不会被误算为落后。例如，100,000 股、60 步时，每步平均基础份额约为 1,666.7 股。第 42 步开始时还剩 19 步，线性计划剩余量约为 31,666.7 股；实际剩余量超过该目标才算落后。

**关键点：**42、51、57 步不是 C 的启动门槛。它们只是原方案里的时间参照点。学习型 C 在任何一个“确实落后”的决策步都能选择启动或等待。

| 参照时间步 | 已经过时间 | 在学习型 C 中的作用 |
|---:|---:|---|
| 第 42 步 | 20 分 30 秒 | 分析策略何时开始介入的参照点，不强制触发 |
| 第 51 步 | 25 分钟 | 中后段参照点，不强制触发 |
| 第 57 步 | 28 分钟 | 临近收盘参照点，不强制触发 |

## 3. C-Q 头看到哪些状态信息

C 头将连续状态离散化后作为 Q 表键。状态向量为：

```text
(当前准确步数, 进度缺口档, 价格偏离档, 自身挂单档, 对手上一期成交档)
```

具体含义如下：

1. **当前准确步数**：0–59。普通交易 Q 头使用较粗的时间阶段；C 头保留准确步数，用来学习启动时点。
2. **进度缺口档**：计算当前剩余量相对于线性计划剩余量的比例，再按 1.05、1.20、1.50、2.00 等阈值分档。缺口越大，档位越高。
3. **价格偏离档**：当前中间价相对初始价格的偏离，划分为低于 -2 bp、-2 至 +2 bp、高于 +2 bp 三档。
4. **自身挂单档**：无挂单；较新且前方队列较短的挂单；较老或前方队列较深的挂单。
5. **对手上一期成交档**：对手上一时间步的成交量是否达到一个基础份额。

这些信息让 C 头不仅能学习“第几步要不要加急”，还可以区分“当前缺口大小、价格位置、挂单是否值得继续等待、对手刚才是否大量成交”等情形。

## 4. C-Q 头可以选哪些行动

当进度落后时，C 头的行动集合如下：

| 行动编号 | C 头选择 | 对普通执行动作的影响 | 报价上限 |
|---:|---|---|---|
| 0 | 不启动 C（no-C） | 保留普通 Q 头选出的基础动作 | 按基础动作自己的报价执行 |
| 1 | IOC +1 tick | 将动作下限提升为 IOC | 卖一价上方 2 ticks |
| 2 | IOC +3 ticks | 将动作下限提升为 IOC | 卖一价上方 4 ticks |
| 3 | IOC +6 ticks | 将动作下限提升为 IOC | 卖一价上方 7 ticks |

基准 IOC 本来就把限价设在卖一价上方 1 tick；C 选项是在基准上继续上移。因此“IOC+3”是额外上移 3 ticks，不是总共只在卖一价上方 3 ticks。

当前最小价位为 1 bp。若中间价约为 100 元，一个 tick 约为 0.01 元；实际限价随当前中间价计算。示例中 IOC+3 的最终价格上限约为卖一价再上方 4 ticks。

普通 IOC 的数量倍率为每步基础份额的 2 倍，并受当前剩余母单量限制。学习型 C 不再额外随机或按缺口强制放大“追赶数量”。C 选择加急时，实际成交数量仍由订单簿匹配决定。

## 5. 一个 Agent 每个 30 秒步的实际流程

以下流程对 A 和 B 分别执行；双方使用同一笔交易前市场快照同步决策。

### 第 1 步：更新订单簿和观察状态

环境先处理挂单过期、报价变为可成交等情况，然后为 A、B 分别构造观察。每个 Agent 能看到自己的库存和当前挂单，也能看到对手上一时间步的成交量；它不会提前看到对手本步将采取什么行动。

### 第 2 步：普通执行 Q 头提出基础动作

普通 Q 头依据自身状态选基础动作。例如选择等待、挂被动限价，或提交基准 IOC。训练时按 ε-greedy 方式探索；评估时使用冻结的 Q 表。

### 第 3 步：检查进度并运行 C-Q 头

若剩余母单在计划内，C 头返回 `no-C`，本步不会触发加急。

若剩余母单落后，C 头将准确时点和其他状态映射到 C-Q 表，再通过 ε-greedy 选择 `no-C`、IOC+1、IOC+3 或 IOC+6。这样，C 头可以在第 42 步之前选择加急，也可以在已经落后时先选 `no-C`，后面再选择更积极的措施。

### 第 4 步：合并两个决策头的选择

如果 C 头选 `no-C`，普通执行头的动作和报价保持原样。

如果 C 头选任一加急档，程序把基础动作下限提升为 IOC 动作 4，并把额外 tick 数传给限价报价函数。普通 Q 头仍提供基础动作，但最终是否采用基础动作、是否加急由 C 头的行动共同确定。

### 第 5 步：将订单提交给模拟订单簿

若 Agent 有旧挂单，可能需要撤销或替换。随后生成限价和子单数量。C 加急时，子单按 IOC 基础动作的 2 倍基础份额计算，最多不超过未完成母单量。

### 第 6 步：根据限价、队列和卖盘撮合

IOC 只能成交价格不高于其限价上限的可见卖盘。卖盘不足时可以部分成交；未成交余量会被 IOC 取消。普通被动订单则可能排队等待主动卖出订单、部分成交或过期。

因此，下列三个数量必须区分：

- **提交数量**：Agent 发出的子单股数；
- **普通撮合成交数量**：模拟订单簿实际撮合成功的股数；
- **收盘兜底数量**：60 步普通撮合结束后仍未买入、由环境补足的股数。

只有普通撮合成交才会减少 Agent 的剩余母单；提交量不能直接算成交。

### 第 7 步：更新价格、库存和下一状态

环境将双方本步实际成交量、随机订单流和市场冲击用于价格更新，然后按实际成交扣减各自库存。下一时间步的状态包含新价格、新库存、新挂单和对手本步实际成交量。

### 第 8 步：计算学习奖励并更新两张 Q 表

如果处于训练模式，普通执行 Q 头和 C-Q 头分别用自己的状态和行动更新各自 Q 表，但使用来自同一环境转移的本步学习奖励。A、B 都完成本步决策与市场转移后再更新，保持双边同步学习。

### 第 9 步：进入下一步或结束回合

重复以上流程直到 60 步结束。自主完单模式下，环境在最后一步普通撮合后对残余母单进行单独计量的收盘兜底。

## 6. C-Q 头如何学习

C 头采用 Q-learning 更新：

```text
Q_C(s_t, a_t) ← Q_C(s_t, a_t)
              + α × [r_t + γ × max_a Q_C(s_{t+1}, a) − Q_C(s_t, a_t)]
```

其中：

- `s_t` 是当前 C 状态；
- `a_t` 是 no-C 或三种加急措施之一；
- `r_t` 是这一步真实环境结果生成的学习奖励；
- `s_{t+1}` 是撮合、库存更新和价格更新后的下一 C 状态；
- 当前 α=0.15、γ=0.98。

终止步没有下一状态，因此终止目标只使用本步奖励。下一状态价值只在已经访问过的合法行动中计算，避免未访问行动初始 Q 值为 0、但实际收益较差时仍被错误选中的问题。

### 奖励中的三类信号

1. **执行成本信号**：根据实际成交价格、手续费、交易冲击等，奖励更低的实际执行成本。
2. **逐步进度缺口惩罚**：若本步后剩余母单超过后续时间的线性计划量，按缺口和母单比例扣分。当前系数为 10 bp。
3. **终局残余惩罚**：最后一步后仍由环境兜底的股数（自主完单模式）或仍未成交的股数（无兜底模式）按母单比例扣分。当前系数为 1,000 bp。

这些惩罚是训练信号，不计入对外报告的经济交易成本。C 头可能从经验中学到：若过早大幅提高报价使成交成本增加，即使减少兜底量也未必更划算；若过度等待导致终局残余增加，则会受到惩罚。

## 7. 训练时探索与冻结评估

### 训练阶段

训练每一回合，C 头以 ε-greedy 方式探索。默认探索率从回合早期 0.35 逐步下降到 0.05：

- 概率 ε：从当前合法行动中随机选一个，以积累不同决策的经验；
- 概率 `1−ε`：从当前状态已访问过的行动中，选 Q 值最高者；若并列，则使用独立、可复现的随机数流打破并列。

普通执行头和 C 头各自使用独立随机流，避免 C 的探索额外改变市场外生随机事件。

### 评估阶段

评估时冻结两张 Q 表，不再更新。对一个从未学过的 C 状态，安全回退为 `no-C`；对有访问记录的状态，只在访问过的合法行动中选择 Q 值最高者。比较多个执行方式时，可以固定训练检查点、使用相同市场随机种子，分别评估关闭 C、固定 C、随机 C 和学习型 C。

## 8. 场景举例

假设第 42 步开始时，A 尚有 40,000 股未完成。此时线性计划剩余量约为 31,667 股，因此 A 落后约 8,333 股，C-Q 头开放四种行动。

- 若 C 头选 `no-C`，普通 Q 头照常决定被动报价或基础 IOC。
- 若选 `IOC+3`，本步动作下限提高到 IOC，报价上限为卖一价上方 4 ticks；IOC 子单最多按约 3,333 股计算（2 × 1,667 股基础份额），并受剩余母单量限制。
- 假设该限价内只有 1,000 股可成交，则 Agent 只买入 1,000 股，其余 IOC 数量取消。实际库存减少 1,000 股，而不是提交的 3,333 股。
- 成交价格、手续费、进度缺口、下一步库存和终局结果共同影响该 C 状态—行动的 Q 值。后续遇到类似状态时，C 头将更倾向于历史回报更高的行动。

第 42 步只是本例的观察时间；相同机制也能在第 42 步之前启动，或在落后后暂缓并在后续步采取措施。

## 9. 完成率和兜底的正确解释

IOC 的限价和可见卖盘约束真实成交，因此 C 不能保证每个加急子单成交。自主完单配置会在所有 60 步普通撮合结束后，对剩余母单使用合成冲击价格模型兜底，以保证模拟任务最终结清。

因此报告中应分开展示 Agent 普通撮合成交量、兜底成交量和兜底成本贡献。模拟完成率 100% 在该配置下由环境兜底保证，不能表述为学习型 C 已经保证盘中全部成交。C 的实验目标是减少兜底、控制成本；是否实现要看配对实验结果。

## 10. 与旧 C 方法的区别

| 方法 | 启动方式 | 选择措施的方式 | 是否通过 C-Q 学习 |
|---|---|---|---|
| 关闭 C（纯 Q） | 不启动 | 普通 Q 头单独决策 | 否 |
| 固定 C | 按预设截止阶段触发 | 阶段规定动作下限和报价档 | 否 |
| 随机 C | 落后时按阶段概率介入 | 随机抽取动作下限、报价和追赶量 | 否；随机 C 是旧对照 |
| **学习型 C** | 任何落后决策步均可选启动/等待 | 从 no-C、IOC+1、IOC+3、IOC+6 中选择 | **是** |

学习型 C 的“随机”主要出现在训练探索和并列行动的随机破局中；冻结评估的行动由已学习 Q 表决定。它不是每步纯随机抽档。

## 11. 运行与查看轨迹

在 `multi_agent_execution` 目录训练学习型 C：

```powershell
python .\run_experiment.py --deadline-c-mode learned --output-dir .\outputs\advanced_self_play_autonomous_learned_c
```

使用已经训练好的最终检查点导出一段说明轨迹：

```powershell
python .\export_self_play_trace.py `
  --checkpoint-file .\outputs\advanced_self_play_autonomous_learned_c\checkpoint_qtables_run1.json `
  --checkpoint 500 `
  --seed 20261110 `
  --scenario normal `
  --deadline-c-mode learned `
  --output .\outputs\advanced_self_play_autonomous_learned_c\sample_learned_c_episode.csv
```

轨迹会逐步记录 C 决策是否开放、C 状态、所选行动、C-Q 值、最终普通执行动作、限价、实际提交与成交、兜底数量和学习奖励。轨迹用于解释单个回合，不应代替跨种子汇总评估。

## 12. 机制边界

当前 C 决策头是有限状态、离散行动的表格型 Q-learning。它能根据模拟经验自主选择行动，但受状态分箱、有限训练预算、双边同时学习的非平稳性和合成订单簿设定影响。某一轮模拟中表现更好不等于证明策略已经收敛，也不保证在真实市场或不同参数下仍然优于规则策略。
