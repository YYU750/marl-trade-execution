# 学习型方案 C：Agent 自主选择加急时点与措施

本文说明当前学习型方案 C 的代码机制。其设计目标是让 Agent 学习 C 内部的具体选择，包括“什么时候开始加急”和“选择哪一档加急”，而不是在预设时间点机械触发固定措施。

需要逐步了解完整决策顺序、状态变量和更新公式时，另见[学习型方案 C 机制详解](./学习型方案C机制详解.md)。

## 1. 研究场景与任务边界

两家机构 A、B 在 30 分钟执行窗口内各买入 100,000 股。一个决策步为 30 秒，共 60 步。每一步，Agent 根据自身剩余订单、价格、挂单和对手上一期成交信息决策。限价订单是否成交由合成订单簿中的可见卖盘、队列、订单流和限价共同决定；提交股数不等于成交股数。

当前自主模式在第 60 步普通撮合结束后，仍由环境对残余母单执行单独计量的收盘兜底。这保证模拟任务按时完单，但不表示盘中 Agent 必定自主成交全部订单。学习型 C 的目标是尽可能减少这部分兜底量，同时控制平均执行成本。

## 2. 两个协同的 Q 决策头

每个机构 Agent 包含两个独立的表格型 Q-learning 决策头：

1. **普通执行头**：从原有五个订单动作中选择等待/保留、被动限价单、价差内限价单或基准限价 IOC，并确定常规子单数量。
2. **方案 C 决策头**：当订单落后于进度计划时，决定本步是否启动 C，以及选择哪一档报价加急。

两个决策头分别维护 Q 表，但都基于同一市场转移和同一实际成交奖励更新。C 决策不是在训练结束后贴上的固定规则覆盖。

## 3. 进度判断与 Agent 的决策时点

令执行步数为 `H=60`，当前零起始步为 `t`，母单总量为 `Q`，当前未完成股数为 `R_t`。当前步决策前的计划剩余量定义为：

```text
S_t = Q × (H − t) / H
```

若 `R_t ≤ S_t`，Agent 尚未落后，C 头只能选 `no-C`，普通执行头正常决策。若 `R_t > S_t`，Agent 已落后，此时 C 头可在四种行动中选择。

检查点材料中的第 42、51、57 步约对应 20 分 30 秒、25 分钟和 28 分钟。它们在本实现中是**分析参照节点**，不是触发门槛。只要落后，Agent 在任意时间步都可以启动或暂缓 C；因此既可以早于第 42 步启动，也可以在前一阶段选择等待，再于后续时点升级措施。

## 4. 学习型 C 的状态和行动

### 4.1 状态输入

C 头使用以下离散状态：

- 准确时间步 `t`，取值 0–59；
- 剩余库存相对线性计划的缺口比例档；
- 当前中间价相对初始价的偏离档；
- 自身挂单状态：无挂单、较新的浅队列挂单、较老或较深队列挂单；
- 对手上一时间步成交量相对基础份额的档位。

准确步数作为状态的一部分，给 Q 表提供学习启动时点的能力。其他状态用于区分不同缺口、行情和挂单环境下是否值得加急。

### 4.2 行动集合

仅在落后状态下，行动编号如下：

| 编号 | Agent 选择 | 撮合参数的变化 |
|---:|---|---|
| 0 | `no-C` | 执行普通 Q 头提出的原动作和报价 |
| 1 | IOC + 1 tick | 动作下限提高到 IOC，基准 IOC 报价再上移 1 tick |
| 2 | IOC + 3 ticks | 动作下限提高到 IOC，基准 IOC 报价再上移 3 ticks |
| 3 | IOC + 6 ticks | 动作下限提高到 IOC，基准 IOC 报价再上移 6 ticks |

本模型的基准 IOC 限价为当前卖一价上方 1 tick。因此三档 C 报价上限分别为卖一价上方 2、4、7 ticks。IOC 仅能成交限价以内当时可见的卖盘；若流动性不足，部分余量会被取消，并不按提交量强制成交。

IOC 的普通动作数量上限为每步基础份额的 2 倍，并受当前剩余母单数量限制。学习型 C 不另外强制补入“追赶数量”，也不把子单提交量直接记作成交量。

## 5. 每个 30 秒时间步的完整顺序

1. **更新可观测状态**：读取双方本步决策前的同一市场价格快照；每个 Agent 读取自己的剩余量和挂单，并读取对手上一时间步成交量。
2. **判断进度**：分别比较自己的 `R_t` 和 `S_t`。在计划内时，C 行动集仅含 `no-C`；落后时开放四档 C 行动。
3. **分别选择行动**：普通执行头按 Q 表及 ε-greedy 规则选基础交易动作；C 头独立按自己的 Q 表和同一训练探索率选择 C 行动。A、B 在同一快照下同步决策，不会先看到对方本步选择。
4. **合并本步执行参数**：若 C 选 `no-C`，保留基础 Q 动作。若选 IOC 加价档，则把动作下限提高到 IOC，并把所选额外 ticks 传给报价函数。
5. **提交子单**：按基础动作对应数量、未完成订单上限和挂单规则提交。原有挂单可能被替换；被动订单记录队列位置和有效期。
6. **执行订单簿撮合**：按限价和可见深度撮合 IOC，处理被动订单与卖方主动流，更新各方真实成交量。没有成交的 IOC 余量立即撤销，被动挂单则可继续排队或到期。
7. **更新市场和库存**：只按实际成交量扣减母单余量；根据双方真实成交和外生冲击更新价格、卖盘及下一状态。
8. **计算共同学习信号**：根据实际执行成本、进度缺口、终局残余惩罚和下一状态构造学习奖励。终端兜底数量或终端未完成量受到惩罚，但惩罚不并入经济成本指标。
9. **更新两张 Q 表**：普通执行头按“基础状态、实际合并后执行的订单动作、学习奖励、下一普通状态”更新；C 头按“C 状态、C 行动、同一学习奖励、下一 C 状态”更新。终止步不使用下一状态自举。双方都完成当前交易和市场转移后再更新，保持同步学习。
10. **进入下一步或结束**：重复以上过程。第 60 步普通撮合结束后，如仍有余量，自主模式由环境兜底完成并单独记录。

## 6. Q-learning 更新

C 决策头使用常规表格型 Q-learning 更新：

```text
Q_C(s_t, a_t) ← Q_C(s_t, a_t)
                 + α [r_t + γ max_a Q_C(s_{t+1}, a) − Q_C(s_t, a_t)]
```

其中 `r_t` 为当前环境实际成交结果生成的学习奖励；奖励包含交易成本信号、逐步进度缺口惩罚和终局残余惩罚。终止步没有下一状态，因此目标只包含终止奖励。实现中未来最大值只在下一状态已尝试过的可用行动中取，避免未访问行动的零初始化值虚高。

训练早期按 ε-greedy 探索四类行动；随着训练回合推进，探索率降低。冻结评估时不再更新 Q 表，并在该状态已访问过的 C 行动中选择 Q 值最高者。一个状态没有任何已学行动时，冻结策略默认选择 `no-C`，避免用未训练动作冒险。

## 7. 完单与经济指标解释

学习型 C 的 IOC 价格上限和成交量仍受模拟订单簿约束，所以它**不能保证每一笔加急订单都成交，也不能单靠 C 保证按时完成全部母单**。若启用 `completion_mode=autonomous`，所有普通撮合结束后环境仍会对余量执行合成收盘兜底；报告必须区分 Agent 普通撮合成交与环境兜底成交。

评估至少同时记录：平均执行成本、终端兜底股数及成本贡献、完成率、Maker/Taker 成交量、C 四类动作频数和配对种子上的差异。学习惩罚只用于训练，不应当作经济执行成本。策略是否改善应以同一冻结检查点、同一场景、同一随机种子的结果检验；不能只凭训练回报或更复杂的算法结构推断效果。

## 8. 运行命令

训练学习型 C（默认 500 回合、5 个训练种子、每场景 30 个评估种子）：

```powershell
python .\run_experiment.py --deadline-c-mode learned --output-dir .\outputs\advanced_self_play_autonomous_learned_c
```

在已训练的策略检查点上进行纯 Q、确定性 C、随机 C 和学习型 C 的配对对照，并额外输出学习型 C 的动作频数：

```powershell
python .\compare_deadline_c_overlay.py `
  --checkpoint-dir .\outputs\advanced_self_play_autonomous_learned_c `
  --output-dir .\outputs\c_overlay_comparison_with_learned_c
```

输出包括 `c_overlay_raw.csv`、`c_overlay_summary.csv`、`c_overlay_paired_differences.csv` 和 `findings.md`。只有从 `--deadline-c-mode learned` 训练并保存的检查点才包含可用的 C Q 表；对不含学习型 C 表的纯 Q 检查点运行该比较会被拒绝，以免将“未训练、总是 no-C”误报成学习策略结果。

## 9. 配对评估结果

2026-11-06 按 5 个训练种子、每个 500 回合完成学习型 C 双边训练；每个最终检查点在正常波动和两倍波动环境分别进行 30 个配对随机种子的评估，单边手续费为 30 bp。另将同一学习型检查点冻结，使用相同 A/B Q 表和配对市场随机种子比较关闭 C、旧确定性 C、旧随机 C 和学习型 C。正常波动为训练环境，两倍波动作为压力评估。

### 学习型 C 训练与纯 Q 训练基线

将学习型 C 最终模型与先前相同训练规模、相同基础随机种子和奖励参数的纯 Q 基线作最终检查点配对比较。表中的差值是“学习型 C 训练 − 纯 Q 训练”，负数代表兜底股数或成本下降。每个场景、机构有 150 个配对对局；区间为配对均值差的近似 95% t 区间。

| 场景 | Agent | 兜底股数差 | 成本差 (bp) | 成本差 95% 区间 (bp) |
|---|---|---:|---:|---:|
| 正常波动 | A | -55,324 | -10.981 | [-11.716, -10.245] |
| 正常波动 | B | -50,628 | -10.187 | [-10.898, -9.477] |
| 两倍波动 | A | -53,486 | -9.389 | [-10.881, -7.896] |
| 两倍波动 | B | -49,314 | -8.425 | [-9.778, -7.071] |

该对照比较的是两种不同训练方式的冻结策略；即使评估随机种子配对，策略 Q 表也因训练时是否启用 C 而不同。它反映“加入学习型 C 的整套训练配置”相对纯 Q 基线的表现，不是只改变评估按钮后的单一变量实验。

|---|---|---:|---:|---:|---:|
| 正常波动 | 同一 Q 检查点、关闭 C | 51,544 | 51,767 | 47.547 | 47.660 |
| 正常波动 | 确定性 C | 34,842 | 36,250 | 44.049 | 44.337 |
| 正常波动 | 随机 C | 40,155 | 40,741 | 44.734 | 44.953 |

| 两倍波动 | 同一 Q 检查点、关闭 C | 51,846 | 51,503 | 45.933 | 46.353 |
| 两倍波动 | 确定性 C | 37,192 | 35,196 | 42.813 | 43.158 |
| 两倍波动 | 随机 C | 38,171 | 41,796 | 42.867 | 43.797 |
| 两倍波动 | 学习型 C | 10,447 | 11,326 | 39.907 | 39.967 |

同一学习型检查点和配对评估种子下，学习型 C 对照关闭 C，正常波动的 A/B 兜底均值各减少 42,398/39,458 股，成本降低 7.350/7.006 bp；两倍波动下各减少 41,400/40,177 股，成本降低 6.025/6.386 bp。本轮也低于同检查点的确定性 C 与随机 C 均值。结果支持在**当前模拟器、参数和训练预算**下，让 C 的时点和档位由 Agent 学习比固定/随机覆盖更有效；仍不能推出真实市场效果。

### Agent 实际选择频数

只统计落后线性计划、C 决策开放时的平均选择次数（每回合最多 60 步）。按时状态另记为 on-schedule，不混入 no-C 选择。

| 场景 | Agent | 落后时选择 no-C | IOC+1 tick | IOC+3 ticks | IOC+6 ticks |
|---|---|---:|---:|---:|---:|
| 正常波动 | A | 21.5 | 13.1 | 9.8 | 10.4 |
| 正常波动 | B | 23.4 | 11.7 | 10.7 | 9.6 |
| 两倍波动 | A | 21.5 | 13.0 | 10.7 | 9.9 |
| 两倍波动 | B | 22.7 | 12.0 | 10.4 | 10.3 |

这表明 Agent 并非每次落后都立即选最激进档，也会在落后状态下选择 no-C；不同报价档均有实际使用。它只能说明本次训练的冻结策略形成了这些选择，不能单凭频数证明收敛。

## 10. 结论边界

这一实现把方案 C 的启动时点和加急档位都纳入 Agent 的自主决策与强化学习。当前配对模拟结果下，学习型 C 同时减少了兜底量并降低了平均成本，但训练轨迹波动、市场仍为合成订单簿，且策略状态空间和训练预算有限。它不是现实交易系统，也不代表已证明收敛；报告应保留这些边界，不能把模拟发现直接写成实盘结论。
