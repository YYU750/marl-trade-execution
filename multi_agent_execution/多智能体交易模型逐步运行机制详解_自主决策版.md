# 多智能体交易模型逐步运行机制详解（Agent 自主决策 + 终端完单兜底）

> **文档对应版本：** 当前主模型采用 `autonomous` 完单模式。A、B 在全部 60 个盘中时间步都由各自 Q-learning 策略自主选择动作；只有第 60 步普通撮合后，环境才对未成交母单余量启动收盘兜底。本文逐步解释这一运行机制。
>
> **重要口径：** `autonomous` 在模拟环境内保证按时完成全部母单；完成保证来自最后一步的合成收盘兜底，不是 Q-learning 单独学会的能力。兜底价格是教学模拟假设，不代表真实市场一定有足够流动性。

## 1. 先用一句话说明模型

模型让买方机构 A 和买方机构 B 同时在一个合成限价订单簿中执行各自的 100,000 股买入母单。每隔 30 秒，两家机构根据各自状态独立选择限价单动作；环境先处理旧订单和新订单，再按照有限盘口、队列和模拟卖方订单流撮合。只有真实撮合量会扣减母单。默认模式下，环境不根据进度覆盖 Agent 的动作；到第 60 步结束仍有剩余时，合成收盘兜底按带冲击的价格成交所有余量。

这不是大语言模型调用或两个聊天机器人协商的系统。这里的 Agent 是两个维护独立 Q 表的强化学习交易策略；市场环境、订单簿和评估器均由普通程序实现。

## 2. 任务、对象与共同规则

| 对象 | 任务或职责 | 独立状态/数据 |
|---|---|---|
| Agent A | 决定 A 的买入子单动作；训练时更新 A 自己的 Q 表 | A 的剩余母单、A 的活动挂单、A 的 Q 表 |
| Agent B | 与 A 同步决策；训练时更新 B 自己的 Q 表 | B 的剩余母单、B 的活动挂单、B 的 Q 表 |
| 订单簿环境 | 管理限价、排队、部分成交、撤单与到期 | 双方订单、随机盘口深度和卖方主动流 |
| 价格环境 | 计算成交后价格冲击和下一步中间价 | 实际成交量、外生价格冲击 |
| 终端完单兜底 | 默认模式只在第 60 步补足仍未成交的母单余量 | 当前时点与剩余母单 |
| 评估器 | 冻结已训练检查点并交叉组合，记录成本和完成率 | 检查点、场景和配对种子 |

A、B 执行同一类任务、使用同一种算法，但拥有不同的 Q 表和各自的母单。两者会争用同一时间步的合成卖盘与卖方主动流；双方实际成交又会共同影响下一步中间价。模型不是零和博弈，也没有中央控制器替双方联合选择动作。

### 2.1 信息边界

每个时间步，A、B 都基于同一个交易前快照决定动作。各自可以看到当前时间、当前中间价、自己的剩余母单、自己的活动子单和队列信息，以及对手上一时间步的实际成交量。

决策时，A 看不到 B 本步的动作、B 的新订单、B 当前队列或未来随机事件；B 对 A 也一样。环境内部能看到全部订单，是因为撮合器必须处理它们。对手本步成交量只会在下一步成为另一方的观察变量。

## 3. 当前主模型使用的时间与参数

| 参数 | 当前主模型值 | 含义 |
|---|---:|---|
| 执行窗口 | 30 分钟 | 从开始时刻到截止时刻的总长度 |
| 决策步长 | 30 秒 | 每回合共 60 步；这是项目采用的模拟粒度 |
| 每家母单 | 100,000 股 | A、B 各自必须买入的股数 |
| 基准份额 | 1,666.67 股/步 | 100,000 ÷ 60，用于定义 Q 动作的基础数量 |
| 初始中间价 | 100 | 计算买入实施缺口的起始参考价 |
| 半价差 | 2 bp | 最佳买价约为中间价下 2 bp，最佳卖价约为中间价上 2 bp |
| 最小价位 | 1 bp | 合成盘口相邻卖价档之间的价差 |
| 单边手续费 | 30 bp，即 0.3% | 只对实际成交的名义金额收费 |
| 每分钟外生波动标准差 | 2.5 bp | 单步为 2.5 × √0.5 ≈ 1.768 bp；高波动场景再乘 2 |
| 临时冲击系数 | 0.35 bp/基准份额/分钟 | 用于主动成交价格调整及收盘兜底价格假设 |
| 永久冲击系数 | 0.20 bp/基准份额/分钟 | 根据双方实际成交量推动下一步中间价 |
| 挂单有效期 | 4 步 | 一张被动挂单最多等待 2 分钟 |
| Q 学习率 α | 0.15 | 控制每次 Q 值更新幅度 |
| 折扣因子 γ | 0.98 | 给未来奖励的权重 |
| 探索率 ε | 每回合从 0.35 线性降到 0.05 | 控制训练阶段随机试动作的频率 |

主运行入口会把库存风险奖励权重设为 0。学习奖励由实际成交实施缺口、每步根据剩余母单与剩余时间计算的进度缺口惩罚，以及终局对剩余量或收盘兜底量的惩罚组成。后两项只用于 Q-learning，不计入经济成本；默认 `autonomous` 模式仍不覆盖盘中动作。

在 100 元参考价下，一家完成 100,000 股订单的初始名义金额约为 10,000,000；按 30 bp 计算，满额手续费约为 30,000 个货币单位。30 bp 与 0.3 bp 相差 100 倍，不能混用。

## 4. 一回合开始前，环境先准备什么

### 4.1 初始化母单和内部账本

回合开始时，程序把中间价设为 100，把 A、B 的剩余母单都设为 100,000 股。双方初始没有活动子单、历史成交量为零。程序建立各自的实际成交、提交量、撤单量、Maker/Taker/强制成交量、费用和奖励账本。

提交股数和成交股数是两本账：提交量只说明 Agent 报出了多少；成交量必须由撮合事件确认。母单余量只按实际成交减少。

### 4.2 为整回合预生成外生事件带

`make_market_tape` 根据回合种子，在开始时为 60 个时间步预先生成共享外生事件。每一步包括：

1. **外生价格冲击**：均值为 0 的正态随机变化；正常场景标准差约 1.768 bp，高波动场景约 3.536 bp。
2. **卖方主动订单事件数**：服从均值为 1.5 的泊松分布。
3. **每笔卖方订单大小**：使用对数正态分布，均值约为 0.70 个基准份额。
4. **买方被动队列前方的外部深度**：三档均值为 0.12、0.65、1.10 个基准份额。
5. **可被买方主动限价单触达的卖盘深度**：七档均值依次为 0.80、0.55、0.40、0.30、0.22、0.16、0.12 个基准份额。
6. **同价和同时间订单的随机优先顺序**：每一步对 A、B 生成一个 tie order。

实际随机盘口每回合会围绕上述均值波动。这是合成订单簿，不是从真实逐笔数据中还原的市场盘口。策略评估使用配对种子时，不同策略组合会遇到相同的外生事件带；由于成交和永久冲击不同，它们之后的中间价路径仍可能不同。

## 5. Agent 的状态表示：每一步它们如何理解当前局面

每家 Agent 获得一个 Observation，再由 `LimitOrderAwareQLearningAgent` 将其压缩成离散 Q 状态。当前状态编码由 9 个特征组成：

| 状态特征 | 当前编码方式 | 所表达的问题 |
|---|---|---|
| 时间阶段 | 每 10 步一档，共 6 档 | 处于 30 分钟窗口的哪个阶段 |
| 执行进度档 | `remaining / (base_slice × steps_left)`，阈值 0.95、1.10、1.40，形成 4 档 | 母单相对剩余时间是落后、接近还是超前 |
| 价格偏离档 | 中间价相对初始价低于 −2 bp、−2 至 +2 bp、至少 +2 bp，形成 3 档 | 当前价格相对参考价的位置 |
| 对手上期成交档 | 对手成交量是否达到 1 个基准份额，形成 2 档 | 对手上一期是否明显成交 |
| 本方报价档 | 无单、深档、最佳买价、价差内、可成交，共 5 档 | 当前本方挂单处于什么报价位置 |
| 本方订单大小档 | 活动订单余量是否大于一个基准份额，2 档 | 当前挂单规模 |
| 队列档 | 队列前方量是否达到一个基准份额，2 档 | 当前挂单前面大约有多少数量 |
| 订单年龄档 | 活动单是否已存续至少 2 步，2 档 | 当前挂单等待了多久 |
| 最后一步标记 | 是否为第 60 步，2 档 | 是否进入最后一个成交区间 |

可能的特征组合最多为 11,520 个，但 Q 表是稀疏表，只保存实际访问到的状态。波动率被传入观察对象用于描述环境场景，但当前 9 维状态键没有把波动率作为特征；Agent 不会因为读到一个“高波动标签”而直接切换策略。

## 6. Q 表中五个动作各代表什么

每个动作包括一个子单数量倍率和一个报价/订单类型。子单目标数量还会被本方剩余母单上限截断。

| 动作编号 | 名称 | 常规目标数量 | 常规报价和执行方式 |
|---:|---|---:|---|
| 0 | 等待/保留 | 0 | 如果已有活动挂单就继续保留；没有挂单时本步不提交新单 |
| 1 | 深档被动单 | 约 833 股 | 在最佳买价下方一个价位挂单 |
| 2 | 最佳买价被动单 | 约 1,667 股 | 在当前最佳买价排队 |
| 3 | 价差内被动单 | 2,500 股 | 报在最佳买价上方一个价位，通常仍在价差内 |
| 4 | 可成交限价 IOC | 约 3,333 股 | 限价上限为最佳卖价上方一个价位，立即消耗限价范围内可见卖盘，未成交余量撤销 |

当中间价为 100、半价差为 2 bp、最小价位为 1 bp 时，最佳买价约 99.98、最佳卖价约 100.02；动作 1 约为 99.97，动作 2 约为 99.98，动作 3 约为 99.99，动作 4 的普通限价上限约为 100.03。

动作 4 是带价格上限的 IOC 限价单，不是无限价格的市价单。即使 Agent 提交 3,333 股，若限价范围内卖盘只有 2,000 股，也只能成交约 2,000 股，其余 IOC 数量撤销。

## 7. 一个 30 秒时间步的完整顺序

程序在 `episode` 中对 `t = 0, 1, …, 59` 循环。下面的 17 个环节在每个时间步重复；不同之处主要是当前价格、剩余库存、挂单和随机事件。

### 第 1 环节：读取本步外生事件

程序从预生成事件带取出本步价格冲击、卖方主动流、三档买方队列深度、七档卖盘深度和 tie order。事件在双方动作前就确定，Agent 看不到未来事件。

### 第 2 环节：先处理旧挂单的到期

对每家机构检查当前活动子单：

- 如果 `当前 t − 创建 t ≥ 4`，旧单到期，未成交量记录为撤单并释放该订单。
- 如果还未到期，则检查本步中间价变化是否使限价买单达到或超过最佳卖价。若已经可成交，程序把旧挂单标为可成交单，清空排队量，准备参与本步卖盘撮合。

重新报价也会撤销旧单并重新排队，所以新单不会继承旧单的队列优先级。动作 0 则不撤旧单，旧单继续等待、成交或到期。

### 第 3 环节：保存共同交易前快照

程序记录当前 `mid_before`、A/B 各自的剩余母单以及对手上一时间步的实际成交量。A、B 使用同一个交易前中间价，但各自看到自己的当前挂单余量、限价、队列前方量和订单年龄。

本步两个 Agent 都在撮合发生前选动作，因此任何一方不会根据对手本步订单临时改变原始 Q 动作。

### 第 4 环节：Q 策略各自提出原始动作

训练时，Agent 使用 epsilon-greedy：

1. 以 ε 概率从五个动作中均匀随机选择，用于探索；
2. 以 `1−ε` 概率在该状态已实际尝试过的动作中选择 Q 值最高者；
3. 若当前状态还没有尝试过的动作，回退到动作 2，即一个基准份额的最佳买价挂单；
4. 多个动作 Q 值并列时，使用 Agent 自己的随机数流打破平局。

每个训练回合开始时有一个 ε 值；它随着训练回合数从 0.35 线性下降到 0.05。回合内的 60 步使用该回合对应的 ε。

评估时 Q 表冻结。程序只在该状态被访问过的动作中选择最高 Q 值；若该状态没有已访问动作，同样回退到动作 2。冻结评估不会改变 Q 值或动作访问次数。

### 第 5 环节：默认模式保留 Agent 的盘中自主决策

默认 `autonomous` 模式不会在盘中将剩余量与线性计划比较，也不会设置最低动作、抬高报价上限或补大子单数量。程序把 Agent 选出的动作原样交给订单簿撮合。即使 Agent 进度落后或选择等待，环境也不会在第 60 步之前替它改变决定。

这是“自主决策 + 完单任务约束”的边界：Agent 决定什么时候挂单、选择什么价格和数量；环境只在最后一个时间步普通撮合结束后，将仍未成交的剩余母单计为收盘兜底成交。这样保证的是模拟任务按时结清，不等于 Q 策略独立完成全部交易。

`none` 模式仅用于关闭终端兜底的诊断对照；它不会修改盘中动作，但也不保证按时完成全部母单。

### 第 6 环节：形成实际动作和提交数量

默认模式下，Agent 提议动作就是实际动作：

```text
实际动作 = Q 提议动作
常规动作量 = min(本方剩余母单, 基准份额 × 动作倍率)
```

实际提交量就是常规动作量。提交量仍不等于成交量，盘口不足或排队未轮到时，本步实际成交可能小于提交量甚至为零。

训练更新使用实际执行动作索引。默认模式下它始终与 Q 提议动作相同；轨迹仍分别记录提议动作和实际动作，可据此核验没有盘中动作覆盖。

### 第 7 环节：按 tie order 撤旧、挂新和计算队列

程序按本步随机 tie order 处理 A、B 的提交。动作 0 保留旧挂单或等待；动作 1–4 会撤销本方旧单并建立新子单。

若新单是被动限价单，程序估算其队列前方量：

```text
本单前方量 = 本档及更有利档位的外部买方深度
           + 同时更早进入且价格相同或更优的本方/对手新单数量
```

按目前的深度参数，加入队列前的外部深度基准大致为：最积极价差内档约 0.12 个基准份额，最佳买价档约 0.12+0.65=0.77 个基准份额，深档约 0.12+0.65+1.10=1.87 个基准份额。真实每回合深度按对数正态分布随机生成。

双方是同步决策，但撮合仍需要同价订单优先顺序。tie order 用来消除固定偏向 A 或 B 的程序顺序；处于更高限价的主动订单则具有更高价格优先级。

### 第 8 环节：把动作转换成限价和订单类型

正常情况下，动作 1–3 建立被动限价单，动作 4 建立可成交 IOC。对动作 4，限价上限为：

```text
limit_price = best_ask + tick
```

因此动作 4 的限价上限为卖一价上方 1 个价位。若该范围内的卖盘不足，未成交 IOC 数量会撤销；Agent 可在后续时间步再次自主决定是否下单。

动作 0 不会生成新订单；没有旧单时本步就是不下单，有旧单时则保留原报价。

### 第 9 环节：主动限价订单消耗七档卖盘

程序收集所有可成交订单，按报价限价由高到低、订单年龄和 tie order 排序。订单逐档消耗限价范围内的卖盘；七档价格为：

```text
卖一价、卖一价 + 1 tick、卖一价 + 2 ticks、…、卖一价 + 6 ticks
```

每档深度是本步预生成的随机量，同一档卖盘由 A、B 共同消耗。如果单笔 IOC 数量大于可触达的可见深度，它会部分成交。

### 第 10 环节：撤销 IOC 未成交量

对动作 4 的 IOC，撮合后仍然剩余的子单余量立即撤销，记入撤单账本，不会自动排队等待下一步。Agent 下一步要继续尝试时需重新报单并重新排队。

此前已经挂在簿上的普通 GTC 限价单，如果因价格变化而变成可成交但可见卖盘不足，可以保留在簿中继续等待；这与新提交的 IOC 不同。

### 第 11 环节：被动订单通过卖方主动流成交

剩余被动买单按买价从高到低、创建时间和 tie order 排序。卖方主动订单流先消耗各订单前方队列；只有前方量被穿过后，剩余卖流才会进入本方订单并产生 Maker 成交。

如果卖流不足以清空队列，Agent 的被动挂单本步可能零成交；若流量只覆盖一部分订单，也会部分成交。没有成交的剩余子单保留，直到被替换、到期、转为可成交单或截止清理。

### 第 12 环节：第 60 步执行收盘兜底

此环节只在 `completion_mode=autonomous` 且当前为第 60 步执行，并且发生在该步常规 IOC 与被动订单撮合之后。程序先按双方本步常规成交扣减，再计算 A、B 合计剩余量：

```text
q_forced_total = max(0, A 剩余母单 − A 本步普通成交)
               + max(0, B 剩余母单 − B 本步普通成交)
```

若合计量大于零，则按照统一的合成收盘兜底价格一次补足双方余量。该价格的冲击计算是：

```text
数量份额 = q_forced_total / 基准份额
impact_bps = tick_bps × sqrt(数量份额)
           + 临时冲击系数 × 市场冲击倍率 × step_minutes × 数量份额
兜底成交价 = 当前中间价 × [1 + (半价差 + impact_bps) / 10,000]
```

A、B 的剩余量合并进入该冲击计算，双方以相同的合成平均价格补足自己的余量。收盘兜底是环境层规则，不是 Q 表动作，也不是无限免费流动性；它使用一个明确、可审计但未经真实市场校准的价格假设。

如果用 `--completion-mode none`，这一步不存在：母单残余不会被成交，回合报告会保留未完成股数，学习奖励还会加入逐步进度缺口惩罚、终局未完成惩罚和终局机会成本。由于完成约束不同，硬完单模式与 none 的成本不能直接排序。

### 第 13 环节：计算实际成交价、手续费和临时冲击

主动成交量是 A、B 本步 Taker 成交量之和。程序根据双方合计主动成交量计算本步临时冲击：

```text
temporary_impact_bps = 0.35 × 市场冲击倍率 × 0.5分钟
                     × 双方 Taker 成交量 / 基准份额
```

该冲击作为额外价格调整应用到 Taker 成交价；Maker 成交按本方限价计价。强制成交的价格已经包含它自己的合成冲击，不再重复叠加普通 Taker 临时冲击。所有成交都按成交价计算 30 bp 单边手续费；没有成交的股数不收手续费。

### 第 14 环节：更新母单和活动子单

程序把本步 Maker、Taker 和（若有）forced 成交合并，累计到各方实际成交量，并从母单剩余量中扣除。子单提交量、撤单量和成交量分别保留。若母单已完成，剩余活动子单清理；若还未完成而活动订单部分成交，子单余量按其订单生命周期继续存在。

`autonomous` 模式的第 60 步兜底会加入实际成交事件，因此回合结束时双方剩余母单都归零。若使用 `none`，最终剩余母单仍大于零则保持未完成状态。

### 第 15 环节：计算学习奖励与经济成本

当本步至少有成交时，程序计算含手续费加权成交均价：

```text
step_shortfall_bps
  = (本步含费成交均价 / 初始中间价 − 1) × 10,000

step_reward
  = −(本步成交量 / 母单总量) × step_shortfall_bps
```

成交价格和手续费越高，负奖励通常越大；本步没有成交时本步成交奖励为 0。收盘兜底成交也作为实际 fill 进入本步奖励和经济成本，因此不会被隐藏在未完成机会成本里。

每个非终止步还会计算进度缺口。令 `steps_after = 60 - step`，撮合后的剩余母单为 `remaining_after`，基准份额为 `base_slice`：

```text
schedule_deficit = max(0, remaining_after - base_slice × steps_after)
schedule_penalty = 10 bp × schedule_deficit / order_size
```

若剩余量不高于均匀执行计划，进度惩罚为零；落后越多，惩罚越大。这是随时间变化的进度风险代理量，不是成交概率。终止步不再计算进度惩罚，而改用终局残余惩罚：

```text
terminal_residual = 第 60 步普通撮合后的剩余量
terminal_penalty = 1,000 bp × terminal_residual / order_size
```

在 `autonomous` 模式，`terminal_residual` 是交给环境兜底的股数；在 `none` 模式，它是最终未成交股数。终局惩罚只用于学习，不计入经济成本。兜底成交的实际价格、冲击和手续费仍进入成本；经济成本还会单独计入 `none` 模式的未完成机会成本。

### 第 16 环节：更新下一步价格并把对手成交量传递到下一步

双方本步所有实际成交量合计后，环境计算永久冲击：

```text
permanent_impact_bps = 0.20 × 市场冲击倍率 × 0.5分钟
                     × 双方本步总成交量 / 基准份额
next_mid = 当前中间价 × [1 + (外生冲击 + permanent_impact_bps) / 10,000]
```

实际成交包括 Maker、Taker 和收盘强制成交。外生冲击可以让下一步中间价上涨或下跌；永久冲击与双方总成交通常方向一致，会反映买方执行对后续价格的影响。

本步成交量被复制为 `prev_qty`。下一步 A 的状态会接收 B 本步实际成交量，下一步 B 的状态会接收 A 本步实际成交量。它们收到的不是对手的本步提交量。

### 第 17 环节：训练时双方在共同环境转移后分别更新 Q 表

若当前回合处于训练状态，双方都在本步动作已确定、成交已完成、下一价格已计算后更新自己的 Q 表。非终止步 TD 目标为：

```text
target = reward + γ × max Q(next_state, 已尝试动作)
Q(state, action) ← Q(state, action)
                   + α × [target − Q(state, action)]
```

当前 α=0.15、γ=0.98。Q 表中未尝试过的动作不参与下一状态最大值计算，避免成本型奖励为负时，未试动作的零初始值被误认为优于已试动作。终止步没有下一状态，未来价值取零。

更新发生在双方动作和市场转移之后，所以 A、B 的 Q 表仍各自更新，但训练环境对任何一方都随对手策略变化，具有非平稳性。默认模式在训练和冻结评估期间都不覆盖盘中动作；两者都在第 60 步使用相同的终端兜底。

## 8. 一基步数与关键时刻对照

代码内部 `t` 从 0 到 59 计数；日志中的 `step` 从 1 到 60 计数。一个 30 秒时间步表示从该步开始到下一时点的订单和价格变化。

| 日志步数 | 内部 t | 本步开始时间 | `autonomous` 行为 |
|---:|---:|---|---|
| 1 | 0 | 00:00 | Agent 根据当前状态自主选择动作 |
| 42 | 41 | 20:30 | Agent 根据更新后的自身库存、订单和市场状态重新选择动作 |
| 51 | 50 | 25:00 | Agent 继续自主决策；程序不设置最低动作或报价覆盖 |
| 57 | 56 | 28:00 | Agent 继续自主决策；如订单落后，可自主选择更积极动作 |
| 60 | 59 | 29:30 | Agent 自主选取最后一个动作；普通撮合后环境补足残余 |

程序不会添加第 61 步。强制兜底发生在第 60 步的撮合流程内，因此输出完成率是在 30 分钟窗口终点按完整母单计算的。

## 9. 一个具体的自主决策回合例子

假设程序进入第 42 步：这一步开始于执行窗口的 20 分 30 秒处。A 尚有 80,000 股。默认 `autonomous` 模式下，环境不会因其落后而覆盖动作；若 A 的 Q 表选择动作 0（等待），实际动作仍为等待。

此时：

1. 如果 A 选择动作 0，且没有旧挂单，本步不提交新单；母单仍剩 80,000 股。
2. 如果 A 选择动作 4，常规提交量约为 3,333.33 股，限价上限为卖一价上方 1 个价位。
3. 撮合器只按队列与可见深度确认实际成交量；IOC 的未成交余量立即撤销。
4. 下一步 A 根据更新后的自身剩余量、市场价格、订单状态和对手上一期成交量重新选动作。
5. 这一过程持续至第 60 步；此时 Agent 仍先自主选动作并参与最后一次普通撮合。
6. 最后一次撮合后如果仍有余量，环境单独执行合成收盘兜底，保证模拟任务完成。

这个例子说明了三条独立的数量概念：Q 动作对应的常规提交数量、订单簿确认的实际成交数量、终端兜底成交数量。只有后两者会减少母单；终端兜底是环境完成约束，不是 Agent 的盘中决策。

## 10. 一回合结束后，程序报告什么

每家机构至少有以下输出口径：

| 指标 | 含义 |
|---|---|
| `submitted_*` | 所有提交量累计；终端兜底股数也计入该总量 |
| `filled_*` | 所有实际成交量累计；`autonomous` 硬完单模式应达到 100,000 股 |
| `completion_*` | 实际成交量 ÷ 母单总量；硬完单模式由终端环境兜底保证为 1.0 |
| `unfilled_*` | 母单剩余股数；硬完单模式终端兜底后为 0 |
| `maker_fills_*` | 卖方主动流穿过队列后产生的被动成交量 |
| `taker_fills_*` | 主动限价单消耗可见卖盘产生的成交量 |
| `forced_completion_*` | 第 60 步由收盘兜底成交的股数，单独记账 |
| `forced_completion_cost_contribution_*_bps` | 强制成交价格与其手续费相对初始参考价的成本贡献 |
| `schedule_deficit_penalty_*_bps` | 整个回合累计的逐步进度缺口学习惩罚 |
| `terminal_residual_penalty_*_bps` | 终局未成交量或送入收盘兜底的余量惩罚 |
| `cancelled_*` | 被替换、过期、IOC 未成交或截止清理的未成交子单数量 |
| `cost_*_bps` | 经济成本；硬完单模式中含盘中成交、收盘强制成交与所有相应费用 |

训练期间另记录每回合奖励、成本、完成率、成交组成和动作分布；检查点保存 Q 表与访问次数。冻结交叉评估再按 A/B 检查点组合、波动场景和配对种子汇总成本及完成率。

## 11. 训练和交叉评估如何构成主实验

1. 每个训练运行使用不同训练随机种子，并初始化两张空的独立 Q 表。
2. 每个回合中 A/B 同时学习；训练场景为正常波动；Agent 的 Q 动作直接提交给订单簿，环境只在截止步兜底完成余量。
3. 每个回合的探索率按回合数从 0.35 线性降至 0.05。
4. 按 `checkpoint_interval` 保存双方策略检查点，并额外保留第 0 回合策略和最终策略。
5. 评估时复制并冻结 Q 表，避免评估修改训练成果。
6. 将 A 的每个检查点与 B 的每个检查点交叉组合，在正常与两倍波动下运行相同评估种子。
7. 配对种子共享外生价格冲击、卖盘深度、队列深度和卖方主动流；策略引起的成交量与永久冲击路径差异作为结果保留。

默认 5 个训练运行、每个 500 回合、每 100 回合保存一次检查点，形成 0、100、200、300、400、500 六个检查点。每个组合、场景用 30 个评估种子，因此总交叉评估量为 `5 × 6 × 6 × 2 × 30 = 10,800` 回合。

有限检查点中的最低成本策略只称为“候选集最佳反应”。它不等于全局最优策略，也不证明纳什均衡。

### 11.1 历史随机方案 C 联合训练

默认命令仍训练纯 Q 模型。若启用 `--deadline-c-mode stochastic`，每步先由 Agent 按 Q 表提出动作，再在进度落后时随机抽取 C 是否介入、动作下限、报价加价档和追赶数量比例。进度越晚、缺口越大，介入概率和允许的动作范围越高。训练器用最终实际动作档位更新 Q 表，因此 C 是学习行为策略的一部分。

这个历史模式仍由限价单簿决定真实成交，C 只改变 Agent 的动作候选和报价参数。它保留为此前随机 C 实验的对照，不代表 Agent 已学习 C 内部时点选择。

### 11.2 学习型方案 C：由 Agent 决定何时介入以及如何加急

启用 `--deadline-c-mode learned` 后，每个 A/B Agent 同时运行两个表格型 Q 决策头：普通执行头决定基础子单动作；C 决策头负责在进度落后时决定是否以及如何加急。两个决策头分别有自己的状态—动作 Q 表，但都从本步限价订单簿的实际成交、成本、进度缺口和终局残余中学习。

每步先建立交易前观察。若当前剩余母单不超过线性进度目标，C 决策集只有 no-C，此时执行头完全自主决定动作。若当前剩余母单高于计划剩余量，C 决策头可从 no-C、IOC+1 tick、IOC+3 ticks、IOC+6 ticks 中选一档。具体选择不受固定时钟门槛限制，所以它能够学习在第 42 步之前就启动，也可以在较早落后时等待至后续时点再加急。第 42、51、57 步（20 分 30 秒、25 分钟、28 分钟）仅用于把学习出的行为与原建议节点对照。

学习型 C 的状态使用准确步数，以及当前进度差、价格偏离、本人挂单和对手上一步成交信息。选中的 C 行动把基础执行动作下限提高到 IOC，并在基础 IOC 报价上提高对应 tick 数；例如基准 IOC 是卖一价上方 1 tick，C+3 最终就是卖一价上方 4 ticks。限价 IOC 只会匹配其限价以内的可见卖单，剩余量撤销。该 C 行动不强制成交，也不额外伪造成交股数。

训练时，C 头和执行头分别用各自的当前状态、所选动作、同一条实际实现奖励以及各自下一状态执行 Q-learning 更新。C 奖励随加急对实际成本、后续进度和终局兜底量的影响而变；如果过早激进报价推高成本，C 也可能学到减少加急。冻结评估使用已训练 C 表，记录 no-C 和三档加急的次数、兜底成交量及成本。第 60 步之后的环境兜底仍单独报告，不能算成 Agent 成交。

运行和完整机制见[方案 C 学习型决策头说明](./方案C学习型决策头说明.md)。

## 13. 如何正确解释自主模式的 100% 完成

默认 `autonomous` 模式达到 100% 完成，准确含义是：Agent 在 60 步中的每个盘中动作都由 Q-learning 自主决定；第 60 步的普通撮合结束后，模拟环境将尚未成交的母单余量按收盘兜底价格计为实际成交，因此模型结果中 `filled=100,000`、`unfilled=0`。这实现了“Agent 自主执行、系统保证任务结清”的分层设计。

它不代表：

- Q-learning 已经学会仅靠自主限价单完成所有交易；
- 真实交易所一定存在相同数量的卖盘；
- 兜底价格一定可在真实市场实现。

报告成本时必须同时列出总成本、Maker/Taker 成交量、收盘强制成交股数、强制成交成本贡献与完成率。若一方完成率为 100% 但半数订单依赖兜底，正确结论是“Agent 盘中自主决策，模拟环境在终端兜底完成；策略对终端兜底依赖较高”，而不是“Agent 已经稳定自主完成”。

## 14. 当前模拟器的边界

- 七档卖盘、外部队列、卖方主动流和价格冲击都是合成参数，尚未用真实逐笔行情校准。
- 撮合器是课程用简化模型，不实现完整交易所撮合、隐藏流动性、网络延迟或跨市场路由。
- 两家机构都是买方，目标相同；有限卖盘和价格冲击造成互动，但现实机构间激励可能更复杂。
- 终端深层流动性和冲击公式，是为了显式表达“必须完单”约束的模型假设。应做终端冲击敏感性分析，并报告强制成交比例。
- 双边 Independent Q-learning 面对不断变化的对手策略，训练具有非平稳性。单个训练种子、单条曲线或少量配对种子不足以证明收敛或策略优越。
- `none` 与 C 的完成约束不同，不应以原始成本高低直接给策略排优劣。
