# 方案 C 对终端兜底量的配对评估

## 问题与比较方式

这次实验检验：在当前带进度惩罚的双边 Q-learning 检查点上，增加方案 C 的临近截止加急规则，能否减少第 60 步普通撮合后的兜底股数。

比较使用同一组冻结 A/B Q 表、同一合成订单簿、同一手续费和完全配对的市场随机种子。每个波动场景包括 5 个训练种子 × 30 个评估种子，共 150 个配对回合。Q 表来自 500 回合、逐步进度惩罚 10 bp、终局残余惩罚 1,000 bp 的训练。两种方式都保留终端兜底；训练过程未启用 C。

“纯 Agent”组执行冻结 Q 表提出的动作；“Agent + C”组只在评估阶段应用 C 覆盖：如果剩余母单落后于线性进度，达到执行窗口 70%、85%、95% 后将最低动作提升为可成交限价 IOC，并分别增加 1、3、6 个最小价位。加急阶段提交量至少为剩余母单除以剩余步数。Q 表在两组中都保持冻结，不会把 C 改写的动作回写成学习经验。

## 结果

兜底股数越少，表示 Agent 在普通限价撮合阶段自主完成的数量越多。成本是含手续费与模拟冲击的经济执行成本，不含学习惩罚。

| 场景 | Agent | 纯 Agent 兜底股数 | Agent + C 兜底股数 | 减少股数 | 兜底量降幅 | 纯 Agent 成本 (bp) | Agent + C 成本 (bp) | 成本变化 (bp) |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 正常波动 | A | 64,470 | 42,730 | 21,740 | 33.7% | 51.178 | 45.652 | -5.526 |
| 正常波动 | B | 62,937 | 42,558 | 20,379 | 32.4% | 50.841 | 45.623 | -5.218 |
| 两倍波动 | A | 63,933 | 44,107 | 19,825 | 31.0% | 49.296 | 44.356 | -4.940 |
| 两倍波动 | B | 60,640 | 39,405 | 21,235 | 35.0% | 48.391 | 43.343 | -5.048 |

在本组配对模拟中，方案 C 在四种“机构 × 场景”组合里都降低了平均兜底量；平均成本也一并下降。每个回合的总完成率仍为 100%，这是两组共用的终端环境兜底保证。C 组每方平均 19 个时间步处于加急阶段，约 17–18 步的动作档位被上调；即使 Q 已选择 IOC，C 仍会提高其报价上限。

## 解释边界

- 结果表明 C 截止加急在当前合成环境和冻结 Q 策略上减少了兜底依赖；并未证明 C 训练与纯 Q 训练相比更容易收敛，也没有证明这组阈值是最优的。
- 更积极的 IOC 价格上限会触达更多合成卖盘，但真实市场的盘口、排队和冲击没有校准；成本下降不能外推为真实交易表现。
- C 改变了盘中动作自主权。因此当前主模型仍是纯 Agent 决策，C 仅作为可选评估对照，不改变 `run_experiment.py` 的默认行为。
- 每场景 150 个配对回合用于课程项目的小范围验证，不足以支持普遍性结论。

## 复现

先生成默认的带惩罚 Q 检查点，再执行：

```powershell
python .\compare_deadline_c_overlay.py --checkpoint-dir .\outputs\penalty_comparison_shaped_500x5x30
```

日常运行可在默认主模型完成 500 回合后直接运行 `python .\compare_deadline_c_overlay.py`；默认读取 `outputs/advanced_self_play_autonomous_completion/`。上面的命令指定本次报告使用的训练目录。脚本生成 `c_overlay_raw.csv`、`c_overlay_paired_differences.csv`、`c_overlay_summary.csv`、`findings.md` 和 `run_manifest.json`。完整结果保存在 `outputs/c_overlay_comparison_current_model/`。
